# Improve usefulness, then make it discoverable

Plan date: 2026-10-13. The GitHub issues are the authority for task state and blockers. This document records positioning and the intended feedback loop; it does not promise exposure, adoption, ranking, or Stars.

## Who should find it

The first audience is people interested in Instinct's AI personal assistant who want concrete product-design lessons. The second is product designers and builders working on assistant replies, agent task states, permissions, and progressive disclosure.

The promise is a useful artifact: a better message, a comprehensible primary and expanded view, or a permission and recovery flow. The evidence-backed teardown explains the borrowed idea and its limits.

## Search and AI discovery fundamentals

Publish useful, readable static HTML with appropriate titles, descriptions, canonical URLs, language alternates, and internal links. Match structured data to visible facts. Link the primary product and policy sources. Keep the source boundary beside the claim.

[Google's current AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) emphasizes useful content and accessible technical foundations. It does not require a special AI text file or schema. Real FAQ content can help readers; adding FAQ markup does not establish exposure. No GEO percentage from a generic guide is a result for this project.

[OpenAI's crawler documentation](https://developers.openai.com/api/docs/bots) separates search crawling from model-training crawling. GitHub project Pages cannot control the host root robots file through a file in this repository's URL subpath. Check the actual root and live responses; do not invent a robots guarantee.

## A small measurement loop

At publication, record the canonical pages, metadata, installation path, release, and repository state. Later, with authorized accounts, check indexing and search impressions. The [current Google report](https://support.google.com/webmasters/answer/16984139) covers particular generative AI displays; its absence is not a zero across all AI products.

Record actual directory availability and voluntary use. Ask for a sanitized input, output, user consequence, and permission to share. Installation, completion of a useful task, repeat use, public endorsement, and Stars each need their own evidence.

Use early feedback to improve one specific pattern or landing message. A suggested first learning goal is five actual design-task reports; it is not a conversion forecast. Review after meaningful feedback rather than creating an unrequested monitoring platform.
