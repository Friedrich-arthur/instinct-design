# Separate fresh-context paired artifacts

Date: 2026-10-13. These are authored, synthetic briefs shaped like product tasks. They are not customer adoption reports or Instinct runtime observations.

Six separate fresh agents inherited the same configured Codex model and reasoning settings. Each received only its room instructions, the same task brief for its pair, and an output location. Three rooms included a snapshot of the v0.2.1 Skill and its references; the other three did not. No agent received the assessment criteria, expected answers, previous outputs, or knowledge of other runs. The setup requested only local material and no external effects. Activation, individual loaded references, and token usage were not independently verified from per-agent tool transcripts; provided files are not proof of reading them.

A separate reviewer saw each pair once as anonymous A/B artifacts, with the order varied by pair. Five ordinal criteria covered artifact usefulness, state honesty, applicable transfer, evidence discipline, and reader load. Model configuration remained inherited, so this was independent same-model review, not a cross-model panel. Root read all raw artifacts and the review before identifying conditions.

## Finding

The reviewer had a limited preference for the with-Skill travel artifact. The baseline's “方案已备好” could suggest readiness despite the missing meeting time; it also clearly disclosed that missing time, no reservation, and no payment. Root agrees that “候选方案” is clearer, without treating the whole baseline as unusable. Both expert-ledger artifacts retained the table and rejected forced chat. Both microcopy artifacts stayed one sentence and preserved all facts. The last two pairs had no clear preference.

This small run does not establish a reliable advantage, an improvement percentage, or actual user efficiency. Both conditions produced useful artifacts. The Skill supplied a reusable method; the evidence supports these observed behaviors, not a superiority claim. No new universal rule was added because the existing core already distinguishes pending states and respects scope. The v0.3.0 change adds Chinese depth and maintenance tools; this paired run used v0.2.1, not the new Chinese reference.

## Product borrowing: travel

### Task

我们在做出差助理。用户让它准备下周上海出差方案，当前结果是两家酒店和三班航班已找到，但会议时间还未确认，航班报价可能变化，没有预订或付款。已有桌面界面有一张行程卡和侧边详情。

我对 Instinct 感兴趣，想借鉴它来改这个界面。下面是我们目前能确认的公开材料。
- Instinct 官网把产品描述为 personal assistant，可用 text or call 入口。来源 https://instinct.com/ 。这是官网描述，没有运行体验证据。
- Colossus 的 Instinct 访谈目录有 Understanding How Your Agent Works、The Future of Agent Interfaces 和 Human Goals vs. Agent Goals 等章节。来源 https://colossus.com/episode/instinct-the-personal-agent/ 。只有公开目录，没有完整逐字稿。

请给出可交给设计师的中文界面方案，包含主视图、展开内容、会议时间缺失时的恢复方式。说明借鉴了什么、有何依据、在哪种情况不适用，以及怎么检查方案有用。保留现有界面，控制在600个汉字左右。

### Without the Skill

```markdown
# 上海出差界面方案

**主视图**：保留现有行程卡与侧边详情。卡片标题为“下周上海出差”，下方固定显示“找到3班航班、2家酒店｜会议时间待确认｜未预订、未付款”。先展示“方案已备好，确认会议时间后才能判断哪班合适”，不把候选行程画成已安排。主按钮“补充会议时间”，次按钮“查看备选”；卡内保留简短文字输入，让用户直接说“会议改到周三下午”。

**展开内容**：侧边分为“还缺什么”“候选方案”“为什么这样选”。会议时间及到会前所需余量列为待补信息；航班、酒店用同样的字段比较时间、位置、报价和限制，已有信息才显示。每项标明报价查询时间与“可能变化”，未知项写“待核实”。解释推荐时明确依据与条件；会议未定时只展示候选，不给唯一推荐。任何预订入口都先重新查价，再让用户确认具体方案和金额。

**恢复方式**：点击主按钮，在原侧边填写会议日期、开始时间，或粘贴邀请；提取结果需用户核对。选“仍未确认”后保留候选与已填信息，卡片继续显示待确认。用户稍后补充或修改时，只重算受影响的行程，提示哪些候选失效，并允许返回备选。报价失效时提供“刷新报价”，刷新失败仍保留旧值及其时间，不显示为当前价格。

**借鉴与边界**：官网的个人助理、文字或通话入口，支持采用自然语言补充信息；没有通话能力时不放拨打按钮。访谈目录中“理解代理如何工作”“人的目标与代理目标”等章节，只启发展示理由、优先满足按时到会；目录不能证明 Instinct 的具体界面或效果。以上是设计推断，未作运行验证。会议时间已固定、仅查单程票时可简化待确认模块。

**检查有用性**：让用户完成“时间未定→补充时间→报价变化”三段任务，观察能否说清缺什么、下一步是什么及是否已预订，能否恢复操作且不用重填。记录误认已安排、无条件推荐、旧价误用和重复输入次数；出现这些问题就调整信息位置与文案。

依据：本目录 brief.md 所列官网 https://instinct.com/ 与访谈目录 https://colossus.com/episode/instinct-the-personal-agent/ ，未访问外部服务。
```

### With the Skill

```markdown
# 上海出差方案界面

保留现有行程卡和侧边详情，沿用字体、颜色与控件。以下为设计提案，未验证实际产品能力。

**主视图**：行程卡标题“上海出差方案待完善”；首行“已找到 2 家酒店、3 班航班”。紧邻显示“会议时间未确认，暂不能判断航班是否合适”“报价可能变化”“未预订、未付款”。主按钮“补充会议时间”，次按钮“比较酒店与航班”。只用层级和留白突出下一步，避免成功对勾或完成色。

**展开内容**：点击比较打开现有侧栏。酒店按位置、价格、取消条件比较；航班按起降时间、价格、退改条件比较。每项显示来源与报价查询时间；未知字段标“待核实”，不编造推荐排序。选择后回显到行程卡；关闭侧栏保留选择和编辑。后续进入预订前，再展示最新总价、退改条件与具体预订对象，取得相应授权。

**恢复方式**：“补充会议时间”在侧栏提供确定时间、暂定时段、“仍待确认”三个入口；附地点和时区字段。暂定时段只筛出候选，持续标注“暂定”；仍待确认时保留已有候选，允许返回比较，不堵住整个任务。不擅自联系参会人。确定时间后重查冲突和报价，再提示差异。要求草稿刷新后恢复；保存失败时明确提示并保留当前输入。

**借鉴与边界**：[官网](https://instinct.com/)仅公开宣称个人助理及文字、通话入口；[访谈目录](https://colossus.com/episode/instinct-the-personal-agent/)仅确认理解代理、界面和目标等议题。据此提出熟悉入口、结果先行、按需展开；未证明 Instinct 采用上述布局或机制。多人多城、需大量并排比较时，卡片不足，应增加宽表格视图。

**检查有用**：请 5 位目标用户看首屏 10 秒，复述真实进度、缺失信息、是否付款及下一步；再补时间、比较并返回、刷新恢复草稿，检查选择不丢失、键盘可操作、报价变化清楚。模拟查询与保存失败，核对错误可恢复且不会误触预订。未做真实用户测试前，不宣称体验改善。
```

## Counterexample: expert ledger

### Task

我们做的是供财务专家使用的月末对账桌面。用户每天逐行排查上千条交易，当前表格同时显示交易ID、金额、币种、来源、匹配结果和异常原因，支持键盘连续选择、批量标记及过滤。最近设计师想受Instinct启发，把它改成只显示一句总结和一个按钮的聊天界面，其他字段全藏在“更多”里。

事实是当前有37条未匹配记录，其中5条金额超过内部复核阈值；导入尚未完成，0条已提交；缺少供应商列的映射，系统没有证据猜是哪一列。今天不是提交截止日。请直接评审这个改法，给一份中文修改方案和可用的状态文案，涵盖主界面、展开信息和恢复流程。保持专家效率，约500个汉字。

### Without the Skill

```markdown
# 月末对账桌面修改方案

不建议改成“总结＋按钮”的聊天界面。专家需要跨行比较、定位异常和连续操作；隐藏关键字段会增加反复展开的成本。可借鉴 Instinct 的清晰层级，但主工作区应保留表格。

**主界面**：固定显示交易ID、金额、币种、来源、匹配结果、异常原因；保留键盘连续选择、批量标记、过滤和撤销。顶部放简短状态条，提供“未匹配”“超过复核阈值”筛选；5条超阈值记录显示复核标识与原因，不能仅靠颜色，也不能自动判为错误。主按钮为“设置供应商列”，提交操作暂不可用，并显示原因。

状态文案：“导入未完成：供应商列尚未映射。已读取记录中有37条未匹配，其中5条超过内部复核阈值。已提交0条。”补充：“今天不是提交截止日，可继续排查并保存进度。”37条仅代表当前已读取数据，完成导入后重新统计。

**展开信息**：行详情展示原始记录、匹配依据及处理记录；导入详情展示已完成步骤、缺失映射和提交条件。关键比较字段始终留在表格，详情随键盘选中行更新。

**恢复流程**：用户选择实际供应商列，预览样例并确认映射；系统无依据时不猜列。保存已有标记、筛选和排查位置，从中断处继续导入，避免重复导入。确认保存成功后提示：“导入暂停，当前进度已保存。请修正供应商列映射后继续。”恢复后重新统计并提示新增记录；导入完成、必要复核完成后才开放提交，显示提交范围供核对，避免一句总结掩盖未完成工作。
```

### With the Skill

```markdown
不建议改成一句总结加按钮的聊天界面。财务专家靠字段横向比较、连续选行和批量操作排查交易；把字段藏进“更多”会增加点击，遮住异常证据。借鉴清晰状态和克制层级，保留对账表格。

主界面继续显示交易ID、金额、币种、来源、匹配结果、异常原因；保留键盘连续选择、批量标记和过滤。顶部显示当前37条未匹配、其中5条超过复核阈值、0条已提交；计数可直接过滤。用文字及轻量颜色标识需复核记录。主操作为“配置供应商列映射”，提交入口显示禁用原因。

状态文案：“导入未完成，供应商列尚未映射。当前37条未匹配，其中5条金额超过内部复核阈值；0条已提交。请配置映射后继续导入。”这些是当前数量，不能当作最终总量。今天无提交截止，不弹紧急提醒。

展开采用行侧栏，入口明确写“查看匹配依据”或“查看原始记录”，展示候选匹配、差异、源数据与标记历史；关闭后焦点回原行，保留筛选、选择和编辑。

恢复时列出源文件表头及样例，由用户指定供应商列，校验后从中断处继续，防止重复导入；系统不得猜列。失败文案：“导入失败；0条已提交。请检查供应商列映射后重试。”方案要求保存映射、标记和进度；只有保存成功才显示“已保存”。导入完成且必要复核通过后，再显示具体提交范围。

验收重点：千行键盘操作顺畅、展开不丢焦点、重试不重复、重开可恢复；详情按需加载。以上为设计方案，功能与持久化仍需实际验证。
```
