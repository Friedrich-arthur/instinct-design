# 结果先行，能力按需展开

用户先知道发生了什么、对自己有什么影响、下一步该做什么。系统把研究、比较、工具与状态管理放在背后；用户需要判断或编辑时，能力和证据才展开。这是本 Skill 的产品设计主张。

## 要改善的产品问题

AI 产品常把能力列表、执行过程和长解释展示给用户，却让用户自己判断任务是否完成、是否可靠、下一步怎样处理。本方法把设计起点放在用户想完成的事，并保持结果、费用、权限和失败状态清楚。

适用对象包括 AI 助理、任务自动化、生成结果页、消息与通知、已有业务工作台。沿用产品既有的用户语言、品牌和专业工作方式。专业用户需要的密度和深度按任务保留。

## 从理念到设计动作

| 理念 | 产品动作 | 检查依据 |
| --- | --- | --- |
| 用户为结果而来 | 先定义用户任务、约束和完成证据，再组织功能 | 用户能说清做什么、完成是什么 |
| 好懂、可预测 | 主动作名称说明后果，状态与真实结果对应 | “准备好”与“已发送”不会混淆 |
| 熟悉入口 | 优先复用当前工作流；比较和编辑用合适的结构界面 | 不要求用户学习无必要的新入口 |
| 结论先行、说人话 | 首句给结果、建议或需注意的事，紧接关键边界 | 只读预览也不会作出错误判断 |
| 前台极简 | 当前任务、主动作、关键限制最醒目 | 不被日志、参数和装饰抢走注意力 |
| 后台能力按需展开 | 理由、备选、证据、编辑与高级控制可展开 | 找得到细节，回得去原任务 |
| 信任持续积累 | 已有授权延续；新承诺呈现具体结果后再决策 | 权限与代价符合实际任务范围 |
| 主动但懂分寸 | 重要、可行动且有时间后果才打断 | 无行动必要的后台事件不反复通知 |
| 美感降低理解负担 | 用层级、留白、可读字体、一致控件和克制动效 | 首屏清楚，失败状态同样清楚 |

## 一个消息的阅读顺序

先给结论或当前状态。接着放会改变判断的影响、费用、限制和不确定性。需要用户行动时，说明具体下一步。理由、证据、备选和实现细节随后按需展开。

例如：“视频已导出，但还没发布。草稿已保存，需要时可以重试上传。”展开后才出现平台错误、导出文件与上次尝试记录。没有真实发布期限时，不凭空制造紧迫感。

这是一种阅读顺序，不是固定字数或每次必填的模板。确认成功的一句话、复杂方案和专家诊断可以有不同长度。

## 首屏、展开层与后台

首屏给用户判断和行动所需的信息。展开层提供来源、理由、比较和编辑。后台管理执行、上下文、验证和技术记录。费用、授权、严重失败和关键不确定性留在首屏附近，不折叠到“更多”里。

展开优先保持当前对象和编辑状态。复杂结果可进入表格、文档或独立结果页。聊天是可选入口；大量对比、精确编辑和专业工作台由任务决定形式。

产品需明确运行中、等待具体决定、完成、部分完成和失败等相关状态。失败时保留草稿，说明恢复动作。要承诺持久化，就要规定哪些内容跨刷新保存并实际验证。设计文档只能定义这些能力。

## 美感的应用建议

既有产品优先保持设计系统。新界面可以从可读字体、中性底色、清楚对比、一处主要强调和一致间距开始。颜色表示动作与状态时，同时配文字；动画解释状态变化，尊重减少动态效果的偏好。

留白帮助分组和阅读，不能让重要信息难找。检查小屏、长中文标签、键盘、焦点、缩放及相关无障碍要求。文案、按钮、详情页和状态用同一个名称。

上述美感规则为原创建议。现有资料不足以复原 Instinct 的字体、配色、圆角、动效或完整品牌规范。

- [消息结构](../skills/instinct-design/references/message-design.md)，处理回复、状态、通知和错误。

交付按用户要求决定形状。只改一条消息时，直接给可用消息。设计界面时，给具体布局、展开与恢复。评审时，先给影响最大的缺陷与修正。不给每个小请求增加完整报告。

## 验收与后续改进

先检查结构与引用，再用具体任务试用，最后让真实用户判断是否更容易理解、预测和控制。实现后需检查用户观感、使用体验、接口一致性、持久化、安全边界、功能、性能与可访问性。分别报告证据，不能用文档、静态画面或一次 Agent 试用代替产品验收。

初版只交付方法、示例和评测请求。后续优先根据真实失败改小规则，保留用户原有工作流，避免越写越大。Star 是传播反馈；采用、复用和实际设计改善另外验证。
