01 / 设计模式

八个思路，
用在真实产品里。

这些模式结合公开观察与作者的设计推断，不声称复现 Instinct 的内部系统。

01

从熟悉的入口开始

消息与通话减少学习新入口的成本。先用用户已经习惯的交互，任务需要时再提供独立界面。

公开观察与应用建议
02

让能力可理解、可预测

说清 Agent 能做什么、当前处于什么状态、有哪些限制。用户应该能预判自己的请求会改变什么。

设计推断
03

消息先给真实结果

先讲答案、影响和下一步。失败或等待中的步骤紧邻结果，确保只读开头也不会误判完成。

原创消息模式
04

前台极简，深度按需展开

让主任务一眼可见，证据和高级控制容易找到。成本、风险、授权和失败不能因为简洁被藏起来。

设计推断
05

权限可以撤回

展示访问范围与断开入口。单独说明撤回权限后，已保存的数据会如何处理。

政策观察与应用建议
06

选择什么时候打扰

只有现在重要、用户可以行动、等待会有后果时才通知。其他更新留在任务视图或汇总中。

原创注意力规则
07

让目标有清晰边界

明确结果、允许的行动、预算和停止条件。范围内沿用已有授权，遇到新边界再请求决策。

设计推断
08

用审美做选择，用实测修正

建立一致的视觉层次，用真实任务检查，包括失败与恢复。好看的原型仍需要验证能否被使用。

02 / 借鉴背后的机制

少一点解释负担，
多一点可用决策。

三个原创建议展示模式如何改变设计。均为合成案例，不是官方截图，也不代表已实测的客户效果。

一条消息

如实表达部分成功。

改进前 “工作流完成。上传异常请查看日志。”

改进后 “视频已导出，帖子仍是草稿。可以重试已保存的上传任务。”

用户只读开头，就知道真实结果与待处理动作。

一个结果页面

让决策容易被检查。

改进前 长聊天混合推荐、原始消息和全部备选方案。

改进后 先展示推荐和未确认成本。证据可以展开，草稿可以原地编辑。

减少视觉负担，同时保留会改变决策的信息。

一个 Agent 任务

行动前说清边界。

改进前 “交给我”没有说明 Agent 可以花多少钱、发什么内容。

改进后 明确任务与预算，先把结果准备好。只有行动超出范围时才请求确认。

用户可以预判外部影响，任务卡住时也有恢复路径。

几个必要的答案

开始前，了解这些。

Instinct design Skill 是什么？

它帮助助手用 Instinct 启发的产品设计哲学优化你的产品。从实际产物找到问题，应用适用原则，交付改稿或实现，并检查同一个用户任务。资料与深拆在需要时展开。

这是 Instinct 官方推出的吗？

不是。Friedrich-arthur 独立维护此仓库，与 Instinct 无关联，也没有官方背书。来源链接标注公开材料，案例与设计建议为原创内容。

这里的 REA 逆向拆解指什么？

REA 指 Reverse Engineer Anything。从可观察的体验推断可能的设计机制，再验证迁移到自己产品后的效果。每项判断都保留证据和不确定性，不涉及恢复私有代码，也不证明内部架构。

Skill 能修改产品代码或接入账户吗？

它指导助手修改已授权的产品代码并检查受影响任务。Skill本身提供指令，不提供账号集成或自主助理服务。外部账号动作仍取决于宿主工具和用户授权。

可以商用吗？实际效果得到证明了吗？

仓库原创内容采用 MIT 许可；第三方品牌与链接内容保留原有权利。仓库提供案例与定性检查，但这不证明用户效果已经提升。采用建议前，请用自己的真实任务验证。

证据可以回看

让来源，
留在思路旁边。

公开观察。Instinct 官网介绍了消息与通话入口。Colossus 访谈页面列出了可理解性、审美、信任和目标追求等话题。官方隐私政策说明了权限和账户控制。

设计推断。八个模式将这些材料与作者的研究转为可复用建议。结论先行的文案、打扰练习和本页面的视觉风格均为原创应用，不是已核验的 Instinct 内部实现。
