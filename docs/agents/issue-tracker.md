# Issue tracker

Use GitHub Issues in `Friedrich-arthur/instinct-design`. Inspect existing issues before creating a duplicate. Each task delivers one independently inspectable result and has explicit acceptance criteria.

Use native GitHub blocking dependencies. Where the API is unavailable, reference real issue URLs in a Blocked by section and preserve the recorded gate. GitHub issue state is authoritative; the growth plan is a dated strategy document.

An issue is ready to start when its blockers are closed and its required authorization and inputs are available. Prepared marketing copy is not posted content. Directory acceptance, real feedback, and customer outcomes require their own evidence.

Do not close a parent issue as a side effect of ticket creation. Apply the roles in [triage labels](triage-labels.md).
