01 / Design patterns

Eight ideas you can use
in a real product.

These patterns combine public observations with the author's design inferences. They do not claim to reproduce Instinct's internal system.

01

Start somewhere familiar

Text and calls reduce the need to learn a new entry point. Use the interaction your user already reaches for, then add a dedicated view when the task needs one.

Public observation + application
02

Make capability understandable

Name what the agent can do, its current state, and its limits. A user should be able to predict what a request will change.

Design inference
03

Put the outcome first

Lead with the answer, consequence, and useful next action. Keep a failed or pending step beside the result so a quick read stays honest.

Authored message pattern
04

Reveal depth on demand

Give the main job a quiet first view. Make evidence and advanced controls easy to find. Keep cost, risk, consent, and failure visible.

Design inference
05

Make permission reversible

Show the scope of access and a way to disconnect it. Explain separately what revoking access does to stored data.

Policy observation + application
06

Choose when to interrupt

Notify when information matters now, the user can act, and waiting has a consequence. Keep other updates in a task view or digest.

Authored attention rule
07

Give goals clear boundaries

Define the outcome, allowed actions, budget, and stop condition. Reuse permission within its scope and pause when a new boundary needs a decision.

Design inference
08

Use taste, then test it

Choose a coherent visual hierarchy. Check it with real tasks, including failure and recovery. A beautiful prototype is a proposal until people can use it.

02 / Borrow the mechanism

Less explanation.
More useful decisions.

Three original proposals show how the patterns change a design. These are synthetic examples, not official screenshots or measured customer results.

A message

Keep partial success honest.

Before "Workflow complete. See logs for an upload error."

After "Your video is exported. The post is still a draft. Retry the saved upload."

A fast reader understands what happened and what still needs action.

A result screen

Make the decision easy to inspect.

Before A long chat mixes the recommendation, source messages, and every alternative.

After Show the recommendation and unresolved cost first. Let the user open evidence and edit the draft in place.

Less visual clutter preserves the information that changes the decision.

An agent task

Show the boundary before acting.

Before "I'll take care of it" hides what the agent can spend or send.

After Name the allowed task and budget. Prepare the result, then ask only if the action exceeds that scope.

The user can predict external effects and recover when the task stalls.

A few useful answers

Before you use it.

What is the Instinct design Skill?

It is an independent open-source method for designing and reviewing AI products. It gives your agent short core instructions and focused references for messages, interaction, visual craft, and product analysis.

Is it made by Instinct?

No. Friedrich-arthur publishes this independent repository. It has no affiliation with or endorsement from Instinct. The source links identify public material; examples and design recommendations are original.

What does reverse engineering mean here?

Reverse Engineer Anything means working from an observable experience to a plausible design mechanism, then testing an application. Each claim should retain its evidence and uncertainty. This does not recover proprietary code or verify private architecture.

Does the Skill connect accounts or run an agent?

No. It creates and reviews design artifacts. It does not connect personal accounts, send messages, make payments, or implement autonomous task execution.

Can I use it commercially, and is its effectiveness proven?

The repository's original material uses the MIT license. Third-party brands and linked content retain their own rights. Examples and qualitative checks are available, but they do not establish measured user improvement. Test the Skill on your own task before adopting its recommendations.

Evidence you can inspect

Keep the source
beside the idea.

Public observation. Instinct's official introduction describes contact through text and calls. The Colossus interview page lists topics including understandability, taste, trust, and goal pursuit. The official privacy policy describes permissions and account controls.

Design inference. The eight patterns translate that material and the author's research into reusable proposals. Outcome-first copy, the interruption exercise, and this page's visual style are authored applications. They are not verified Instinct implementation details.
